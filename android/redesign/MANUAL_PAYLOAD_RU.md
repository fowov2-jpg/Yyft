# VipineshkaVPN — ручной HTTP Payload (лаборатория, Android 2.4.8)

Дата: 2026-10-30. Ветка: `feature/vipineshka-russia-one-tap-20261030`.

## Доступ в Android
`Настройки → Ручная диагностика сети → HTTP Payload · вручную`.

1. Выбери «Твой шаблон» (точная форма CONNECT Https://vk.com, [crlf], включая User-Agent твоего Xiaomi) или «Обычный CONNECT».
2. Можно менять любые поля запроса вручную; редактор сохраняет шаблон локально.
3. Обязательно укажи **настоящий адрес и порт принимающего HTTP-шлюза**, который ты контролируешь или которому доверяешь. `vk.com` в заголовках не делает VK таким шлюзом.
4. Выбери TLS до шлюза (проверка сертификата сохраняется) либо RAW (содержание открыто провайдеру).
5. Оставь «Тестировать через мобильную SIM», если хочешь оценить доступность из мобильной сети. Нажми «Проверить один раз».
6. Скопируй статус и сам HTTP шаблон в чат для дальнейшего анализа; **не публикуй секреты, прокси-пароли или токены**.

## Что именно делает тест
- Превращает `[crlf]` в реальные CRLF и формирует один HTTP-запрос до 4096 байт.
- Выбирает физическую сеть Android (`TRANSPORT_CELLULAR` или `TRANSPORT_WIFI`), исключая `TRANSPORT_VPN`.
- Открывает один сокет на **указанный пользователем шлюз**; таймаут TCP 4 с, чтение 4 с. При TLS проверяет сертификат и имя шлюза.
- Отправляет ровно один пакет и получает только первую строку ответа (до 256 байт).
- Не чаще одного теста в 20 секунд; никаких периодических сканов или бесконечных попыток.
- Принимающий шлюз видит отправленный запрос, а в RAW-режиме запрос виден сети.
- Никогда не меняет Xray, VPN-статус, сервер, настройки Kill Switch, маршруты приложений.

## Что тест НЕ доказывает
- `HTTP/1.1 200` от шлюза **не доказывает** возможность передачи произвольного интернет-трафика через VPN и не подтверждает выходной IP Германии.
- Префиксы `Host`, `X-Online-Host`, `X-Forwarded-For` не гарантируют прохождение операторского whitelist. `X-Forwarded-For` обычно IP-адрес, а не URL.
- GitHub Actions runner может проверить компиляцию и форматирование, но не воспроизводит российского оператора и его whitelist.
- Сырой формат HTTP-BUG от TLS Tunnel не совместим автоматически с транспортами Xray (VLESS/REALITY/XHTTP). Для реальной передачи TUN через ручной шлюз необходим согласованный протокол обеих сторон и отдельная интеграция; она пока не реализована.

## CI проверки
- `.github/workflows/build-vipineshka-branch.yml`: распаковка реального `android/source.zip`, существующие патчи SecureConnect, интеграция `apply_manual_payload_lab.py`, `assembleDebug`, `testDebugUnitTest`, `lintDebug`, security audit, проверка подписи APK.
- `ManualPayloadCodecTest`: точные CRLF, сохранение нестандартного шаблона, обычный CONNECT, контроль длины и недопустимых последовательных запросов, запрет ложного статуса VPN.

## Примечание по безопасности телефона
После сообщения о нагреве Xiaomi новая функция доступна **только по нажатию**. Нет фона, бенчмарков, дополнительных Xray процессов, никаких изменений основного соединения.

## Автогенератор (экспериментальная тестовая сборка)
- В том же экране ниже ручного редактора: **«Автогенератор CONNECT-комбинаций» → «Сгенерировать и проверить»**.
- Шлюз: **принадлежащий тебе или разрешённый HTTP CONNECT-прокси** с известными адресом и портом. Поле «Host для заголовков» по умолчанию `vk.com`. Приложение не принимает сайт `vk.com` за HTTP-прокси.
- Генерируются до 24 вариантов `CONNECT`, `Host`, `Referer`, `X-Online-Host`, `X-Forwarded-For`. Используется **один** поток проверок, без случайного перебора чужих адресов.
- Для каждого варианта требуется полноценный ответ `HTTP CONNECT 200`, затем **отдельный TLS handshake с проверкой сертификата example.com** и подтверждённый `HTTP 2xx/3xx` от `example.com` **внутри этого туннеля**. Только это считается успехом **HTTP-прокси**, не Xray или выходом Германии.
- При успехе найденная комбинация сохраняется в локальный ручной редактор. При 24 неудачах тест завершается и **не перезапускается автоматически**.
- Перед каждым запросом проверяется Android thermal status, энергосбережение и системная нехватка ОЗУ; остановка также по кнопке STOP или уходу с экрана. Между запросами 750 мс; сетевые TCP/чтение имеют тайм-ауты 3 секунды.
- Никаких изменений основной VPN-сессии, Kill Switch, Xray-конфига, фоновых сканирований или непрерывного нагрузочного теста.
- Строгая операторская whitelist-фильтрация по IP этим генератором не обходится автоматически; видимые провайдеру TCP/IP и TLS SNI относятся к *реальному входному шлюзу*, а не к `Host: vk.com`.

### Фактическая граница проверки
GitHub Actions может собрать APK и проверить генерацию/валидацию комбинаций, но не имеет твою российскую SIM и не может подтвердить достижимость шлюза в её сети. Для доказанного «выход Германия» требуется рабочая VPN-интеграция через разрешённый шлюз и проверка внешнего IP после создания туннеля.
