# SecureConnect — бесплатный публичный рейтинг (GitHub Actions + Pages)

**Статус комплекта:** код и локальные Python-тесты подготовлены. Публикация и выполнение на GitHub **не подтверждены**. Не считайте пример адреса развернутым сервером или прошедшие Python unit-тесты — успешной проверкой публичных VPN.

## Архитектура и ограничения

- Источники берутся **только** из белого списка `SOURCES` файла `checker.py` (стабильные ID совпадают с `ConfigSources.kt`). В первую очередь РФ: `avia`, `nikita`, `3inker`; добавлены источники резервного пула. Не принимать URL от пользователей, приватные подписки и загружаемый Xray JSON.
- На каждом запуске не более 80 конфигураций, 2 Xray-процесса одновременно, до 20 минут проверки и до 24 минут всего. Ротация по номеру Actions-run. Несуществующие или недоступные источники пропускаются. Максимум 2 URL на источник и 1 MiB на ответ.
- Xray берётся из **официального** `ghcr.io/xtls/xray-core` релиза `26.10.21` с закреплённым immutable **Linux amd64 SHA-256 OCI digest** `447ffc750a0b87d6e4f2c38425f68105bfc8c789e59c22d83b94eb7e1e648c50`. Это digest образа, НЕ SHA ZIP-архива; контейнер копирует `/usr/local/bin/xray` без исполнения установочных скриптов. В отсутствие Docker или доступа к образу workflow завершится ошибкой, фиктивные результаты не публикуются.
- Обязательны публичный IP узла, DNS-разрешение без private/link-local/loopback/CGNAT, закрепление адреса IP перед запуском Xray, SOCKS **только на 127.0.0.1**, HTTPS TLS+валидация сертификата `www.gstatic.com/generate_204`, затем независимо `www.youtube.com/` через тот же SOCKS. YouTube-проверка страницы **не гарантирует 720p**.
- Успешным считается только `https_ok: true`. Из feed никогда не публикуются исходные `vless://`, `vmess://`, `trojan://`, `ss://` URI, реальные пароли, IP или Xray outbound; только SHA-256 fingerprint, ID источника и признаки/время проверки.
- Источник `source_id` должен точно совпадать с `ConfigSource.id`. Fingerprint = SHA-256 от UTF-8 строки URI после trim и удаления всего начиная с первого `#`. Unicode в комментариях не влияет. Эквивалентные URIs с разной кодировкой параметров дают **разные** fingerprints. Тестовые URI `tests/fingerprints.json` — синтетические, не настоящие VPN-сервера.
- Повторно публикуются только ранее действительно проверенные HTTPS-success записи с исходным `checked_at`, если они моложе 8 часов. Новый неудачный пробный запуск удаляет проверенный узел из списка. При нуле новых успехов публикуется корректный JSON с пустым массивом либо с ещё актуальными старыми данными, не «фальшивые зелёные» узлы.

## Ручная публикация с телефона без платежей

1. Через GitHub web (в мобильном браузере при необходимости включите **«Версия для ПК»**) создайте **публичный** репозиторий, например `secureconnect-free-checker`. Если репозиторий уже есть, убедитесь, что он предназначен для этого проекта. Не загружайте в него личные VPN-подписки, ключи, `*.keystore` и секреты приложения.
2. Поместите **содержимое этой папки** в корень репозитория, а не сам ZIP. Не потеряйте путь `.github/workflows/verify-nodes.yml` (папка `.github` скрытая на некоторых файловых менеджерах). Удобнее загрузить через Git в Code on the go или любую бесплатную Git-программу на телефоне. Команды после `git init -b main`: `git add .`, `git commit -m 'Initial free checker'`, `git remote add origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПО.git`, `git push -u origin main`. GitHub потребует вход через credential manager или PAT с ограниченными правами; **не вставляйте PAT в исходники**.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**. Пока страница не включена, `deploy-pages` может не сработать.
4. Вкладка **Actions → Public VPN ranking (bounded Xray checks) → Run workflow → Run workflow**. После завершения откройте два job: `verify` и `deploy`; оба должны быть зелёными. Первый запуск может вернуть пустые `results`, если публичные источники/узлы недоступны из сети Github.
5. Проверяйте опубликованный файл по `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПО/feed.json`: HTTP 200, `"schema":1`, актуальные `generated_at`/`valid_until`, `"results":[...]`. **Это формула URL, а не проверенный действующий адрес!** Если Pages отдаёт 404, проверьте зелёный deploy и настройку Pages, не используйте URL в приложении как работающий.
6. Android: **Настройки → Бесплатный рейтинг GitHub Pages → HTTPS-адрес → Сохранить адрес рейтинга**. Перезапустите приложение или откройте его главный экран. Начальный запуск и восстановление VPN не зависят от загрузки JSON; в диагностике доступны причина fallback, время публикации и число сопоставленных узлов.

В `.github/workflows/verify-nodes.yml` есть `workflow_dispatch`, расписание в 01:23/07:23/13:23/19:23 UTC и запуск при изменении кода/тестов. Scheduled GitHub Actions может опоздать, быть пропущен или отключиться через 60 дней без активности публичного репозитория; тариф публичного standard runner сейчас бесплатен, но **не бессрочный SLA и не гарантия приемлемости конкретной нагрузки по GitHub ToS**. Если GitHub ограничивает проект, уменьшите лимит/частоту или отключите расписание, а не обходите защиту. GitHub запрещает использовать Actions как универсальную серверлесс-службу; загрузка маленького JSON как результата тестов проекта не гарантирует разрешение на регулярную внешнюю прокси-проверку — при сомнении обратитесь в GitHub Support.

Перепубликация сырой подписки **не производится**, но условия каждого внешнего источника могут изменяться: перед включением нового источника проверьте его лицензию и разрешённые методы запроса. Недоступные/отзывающие доступ источники следует исключать.

## Тесты

`python3 -m unittest discover -s tests -v` из корня checker. Должны пройти тесты fingerprint, UTF-8, source parsing, SSRF, DNS pin, дедупликации и TTL. Эти тесты **не требуют сети** и **не проверяют живые VPN**. Для реального теста workflow необходимы DNS/интернет, официальный Xray и публичные источники. Дополнительная ручная проверка должна исключать токены в логах и содержимом feed.

## Безопасность и конфиденциальность

Поскольку URI содержат публично опубликованные учётные параметры, они используются только в краткоживущих конфигурациях Linux runner c правами 0600, удаляются после пробы, stdout/stderr Xray отключены. Это не является гарантированной изоляцией недоверенного кода уровня VM для Xray; если появятся уязвимости в Xray, остановите проверки и обновите закреплённый образ после проверки digest. Запросы только по фиксированным HTTPS URL от GitHub; редиректы заблокированы. Feed клиента Android не может добавлять конфигурации, менять routing, подключать VPN или подтверждать 720p.

## Почасовая проверка (26.10.2026)

- GitHub Actions запускает ограниченный тест в 23-ю минуту каждого часа UTC (`23 * * * *`). GitHub может задержать запуск.
- За один запуск проверяется не более 24 кандидатов в двух потоках; старые подтверждения хранятся только до истечения `checked_at`.
- Для резервного ручного запуска обновите `ops/hourly-trigger.txt`: это вызывает push workflow. Делайте это лишь когда расписание пропущено и другой запуск уже не работает.
- Дополнительная почасовая задача ChatGPT проверяет актуальность `feed.json` и при пропущенном обновлении может отправить резервный триггер через подключённый GitHub. Выполнение зависит от доступности GitHub и инструмента.
- Только публичный репозиторий и стандартные бесплатные runners, без VPS, API и подписок. Соблюдайте [ограничения GitHub Actions](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features).

## Проверка восстановления Xray / GitHub Actions (27.10.2026)

После первичного HTTPS-теста до **трёх успешных публичных маршрутов из разных источников** повторно проверяются запуском нового процесса Xray и нового SOCKS/TLS-запроса. Результат `restarts.json` показывает `restart_ok` и задержку повторной проверки. Ни VPN URI, ни пароли в этот диагностический JSON не включаются. Результат подтверждает **только повторную работоспособность через GitHub runner** — это не тест Android VpnService, TUN, смены сети или работоспособности в мобильной сети пользователя. Лимиты: максимум 24 первоначальные проверки и до 3 повторных, 2 потока.


## CI: инъекция отказов Android (28.10.2026)
В `android/ci-tests/CiFailureRecoveryMatrixTest.kt` находятся тесты существующих решений Guardian/QuickConnect/FastFailover на холодный TLS, повторные ошибки, пропадание физической сети, порядок проверенных/облачных маршрутов и изоляцию ручного выбора. Workflow `android-build.yml` переносит их в тестовый исходный проект и исполняет `:app:testDebugUnitTest`; JUnit XML публикуется отдельным артефактом. Это **симуляция событий и проверка Android Kotlin-политик**, не тест фактического Android VpnService/TUN и не сертификация безопасности APK. Живые подключения Xray на GitHub проверяются отдельным `verify-nodes.yml` вместе с перезапуском реального процесса Xray (до 3 серверов). Play Protect-замечание для debug APK остаётся открытым, новую установку не предлагаем.


## Ограничение длительности VPN-сеанса (29.10.2026)

В настройках SecureConnect теперь предусмотрен **таймер сеанса**: без ограничения, 1, 2, 3, 4, 6, 8, 12 или 24 часа. Отсчёт запускается после нажатия «Подключить» с разрешённым VPN, включая поиск подходящего сервера. Переподключения и смена маршрутов таймер не сбрасывают. Смена выбранного срока во время активного сеанса запускает новый отсчёт; ручное «Отключить» снимает таймер. При истечении приложение через AppRunController останавливает Xray, закрывает TUN, отменяет сканирование и убирает собственную задачу Android. Неподписанный системными правами Android APK **не может программно force-stop весь пакет**. Используется AlarmManager.setAndAllowWhileIdle без разрешения на точные будильники; Android Doze и производитель могут задержать срабатывание. Срок сохраняется и повторно проверяется в Activity и сервисах, чтобы не восстанавливать просроченную сессию. **Предупреждение:** отключение VPN/kill switch в конце сеанса может открыть обычный прямой интернет-трафик.

Новый APK не считается безопасным без отдельного разбирательства с красным предупреждением Play Protect. Unit-тесты/аудит манифеста — не заключение антивируса.


## Глобальный аудит исходников (29.10.2026)

GitHub CI выполняет `security_audit/audit.py` поверх **реально пропатченного** Android-проекта до сборки APK. Проверяет AndroidManifest, экспорт/разрешения VPN-служб, неэкспортируемый таймерный receiver, отсутствие разрешений SMS/камеры/установки чужих приложений, сохранение и завершение времени сеанса, шифрование Android Keystore AES-GCM, пин SHA-256 нативного Xray, отсутствие разрешения небезопасного TLS, обязательные unit-тесты и запрет публикации APK при падении CI. При сбое хотя бы одного правила APK не публикуется; JSON-отчёт сохраняется отдельно. Это статический аудит политик, **не** экспертиза Play Protect, не анализ всех путей исполнения и не тест реального Xiaomi/TUN. Отдельно осталось проверить необходимость разрешения QUERY_ALL_PACKAGES и оформление постоянной release-подписи.

Android Lint нашёл ошибку `QueryAllPackagesPermission` (1 error / 149 warnings). Вместо игнорирования ошибки `QUERY_ALL_PACKAGES` убран в **патче сборки**, и генерируется manifest `<queries>`: только приложения с launcher-иконкой и 125 пакетных ID из списка `RussianApps`. Ограничение: произвольные сторонние приложения без launcher-иконки могут исчезнуть из списка ручной настройки, и их маршрутизация требует отдельной обработки. Проверка полного соответствия 125 ID входит в статический аудит GitHub. Это минимизация разрешений, но **не гарантия** снятия предупреждения Google Play Защиты.


## Устойчивый облачный отбор без новой установки APK (30.10.2026)

GitHub Actions каждые ~60 минут проверяет **до 24 реальных Xray/SOCKS/TLS соединений из своей сети**. До 6 слотов выделяется для *повторной проверки* свежих предыдущих успешных публичных URI (не старше 2 часов; проверка исходной даты, SHA-256 и разрешённого источника), остальные слоты — поиску новых серверов из фиксированных источников. Из 24 положительных результатов до 3 из разных источников дополнительно запускаются в **новом процессе Xray**. Если повторное подключение не прошло, конфигурация удаляется из `candidates.json` и доказательство успеха отзывается в `feed.json`. Успешно переподключённые маршруты сортируются первыми, затем остальные — по HTTPS-результатам и задержке. Формат `candidates.json` **не меняется**, поэтому уже установленный SecureConnect 2.4.8 получает его автоматически; нет необходимости копировать ссылки вручную. Результаты не обещают доступность через МегаФон — проверку в сети оператора делает сам телефон. Списки «белых сайтов» VK/Яндекс и т. п. **не превращаются в VPN-шлюзы**, SNI/TLS не подменяются, расширенные привилегии не запрашиваются. Ограничения: публичным VPN-серверам нельзя доверять конфиденциальную активность; постоянный безопасный собственный шлюз требует отдельной инфраструктуры.


## Дополнительные реальные тесты через Xray (30.10.2026)

На GitHub для трёх маршрутов из повторной Xray-проверки выполняется ещё один HTTPS-запрос через тот же SOCKS5/TLS-туннель к фиксированному публичному `www.google.com/robots.txt`. Проверяется **реальное тело ответа размером не менее 512 байт** с ограничением чтения до 8192 байт. Результаты публикуются в `payload.json`: успех, количество байт и время, без паролей, IP и URI. Это НЕ тест мобильной сети МегаФона, белого списка, upload-скорости или Android TUN: эти поля явно помечены `false`. Неудачная диагностика чужого сайта не отменяет основной HTTPS-успех Xray и не подделывает его. `candidates.json` и APK не меняются.


## Тест отдачи данных через Xray (30.10.2026)

GitHub отдельно проверяет небольшой HTTPS POST через SOCKS5/Xray к фиксированному публичному echo-сервису `postman-echo.com/post`: отправляет синтетический тестовый текст длиной 1043 байта и считает успехом только получение *точного полного отражения* текста по TLS с проверкой сертификата. Максимум три POST за запуск, ответ ограничен 16 КиБ. Результат в `upload.json`: успех, байты и задержка, без конфигураций и данных пользователя. Сбой стороннего диагностического сайта не отбрасывает рабочий VPN; всё ещё нет доказательства скорости upload или прохождения «белого списка» МегаФона, а `android_tun_tested=false`. Никаких изменений APK и схемы `candidates.json`.


## Приоритет двусторонне проверенных конфигураций (30.10.2026)

Серверы с успешным **повторным Xray**, реальным небольшим HTTPS-скачиванием и подтверждённым HTTPS POST/эхо на GitHub получают приоритет в `candidates.json`. Далее идут остальные прошедшие повторный Xray, затем базовые HTTPS/TLS-кандидаты. Это лишь порядок, а **не гарантия пропускной способности** и не утверждение о белом списке МегаФона. При отказе внешнего тестового ресурса рабочие конфигурации не теряются. Не меняются схема JSON, приватные настройки, Android-код и APK; приложение читает тот же адрес автоматически.


## Опциональная диагностика мобильной сети на устройстве (30.10.2026)

Новая кнопка Настройки → «Диагностика мобильной сети» запускает **только по выбору пользователя** 4 коротких HTTPS-запроса (VK, Яндекс, контрольный HTTPS, Github) через `Network.openConnection` с явно выбранной сетью `TRANSPORT_CELLULAR`. Запросы **обходят VPN**; перед нажатием интерфейс предупреждает, что сайты увидят реальный мобильный IP. Ничего не отправляется в репозиторий, VPN-туннель и настройки не меняются. Состояние Xray и доступность сайтов не являются доказательством, что оператор МегаФон причисляет VPN-трафик к VK или повышает скорость — нужны наблюдения через SIM-карту при действующих ограничениях и замеры. Проверки policy/JUnit/Android Lint и статический аудит выполняются в GitHub. Для этой кнопки потребуется **новый Android APK**; существующая автоматическая доставка публичных конфигураций работает в прежнем APK.


## Резервная загрузка готовых конфигураций (30.10.2026)

Устранён сценарий, когда `candidates.json` с GitHub Pages валиден и непуст, но все URI неподдерживаемы текущей версией Android: ранее приложение записывало «успешную» загрузку с 0 серверов и **не пробовало** резервный адрес GitHub Raw. Теперь для такого случая делает вторую попытку с Raw и не продлевает метку успешного импорта без валидных серверов. Пустая корректная публикация не объявляется ошибкой и не приводит к бесконечным циклам. Обновление не отключает Kill Switch, не меняет TLS/SNI и не обходит блокировки обоих доменов GitHub со стороны оператора. Добавлены Kotlin unit-тесты на граничные случаи. Для получения фикса в приложении необходим новый APK — обновлённый серверный JSON сам по себе код установленного APK не изменит. У debug APK пока нет постоянного сертификата подписи и было красное предупреждение Play Protect, так что замена работающего экземпляра остаётся рискованной.


## Исправление неотвечающей кнопки диагностики (30.10.2026)

При нажатии на «Проверить через SIM-карту» интерфейс **сразу** пишет «Кнопка нажата», а затем показывает этапы 1/4–4/4 и накопленные ответы VK, Яндекса, обычного HTTPS и GitHub. Сетевая функция `Network.openConnection` теперь обёрнута в обработку ошибок *включая момент открытия соединения* (на Android 16/Xiaomi её могло блокировать соединение VPN/kill switch); каждый отдельный отказ отображается без прерывания следующих тестов. Добавлен общий лимит 35 секунд и ошибка при его превышении. Никакого обхода системного Kill Switch, никаких принудительных SNI и фона. Unit-тест проверяет отображение промежуточного прогресса, а GitHub Audit — наличие UI-коллбека на главном потоке.


## Исправление совместимости облачного рейтинга без нового APK (30.10.2026)

Найдена реальная несовместимость: `feed.json` содержал 15 результатов `telega_ru` из 85; ранее установленный Android `PublicRankingFeed.parseValid` принимает только исходные `ConfigSources.all` и отклоняет **весь** JSON при одном неизвестном `source_id`. Новый облачный источник `telega_ru` был разрешён только для отдельной загрузки URI через `PublicCandidateSourcePolicy`. Поэтому генератор `feed.json` теперь публикует **только известные старому Android источники**, сохраняя положительные проверки и исходные временные метки. Это исправление серверной публикации: старым APK оно доступно без установки новой сборки, если телефон имеет доступ к GitHub Raw и повторит запрос. `candidates.json` с проверенными URI продолжает включать `telega_ru`. При блокировке GitHub сетью оператора или других ошибках тайм-аутов этот фикс сам по себе не создаёт доступность. Добавлен регрессионный тест обоих контрактов.


## Вывод диагностики при активном VPN — исправление после Xiaomi Android 16 (30.10.2026)

На Xiaomi с включённым VPN и Kill Switch четыре прямых HTTPS-запроса через выбранный `Network` ответили «соединение недоступно». Это **не подтверждает** блокировку этих сайтов МегаФоном: Android не обязан разрешать сетевые соединения мимо активного VPN; настройка Android «Блокировать подключения без VPN» запрещает их. Исправлено поведение: если приложение видит `VpnState.Connected`, оно **не запускает** прямые запросы, а показывает информативное «проверка через SIM-карту не запускалась» и предупреждение о необходимости отдельного добровольного теста без VPN; параметры VPN/kill switch не меняет и не вызывает `allowBypass`. При отсутствии VPN запросы выполняются только после нажатия кнопки и предупреждения о раскрытии мобильного IP целевым сайтам. В названии убрано предположение, будто оператор SIM распознан как МегаФон (он фактически не определяется). В unit-тестах зафиксирован сценарий снимка пользователя, проверяется отсутствие ложного вывода о блокировке. Новая логика требует нового APK, не появится автоматически в установленной версии.
