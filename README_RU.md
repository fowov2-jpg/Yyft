# SecureConnect — бесплатный публичный рейтинг (GitHub Actions + Pages)

**Статус комплекта:** код и локальные Python-тесты подготовлены. Публикация и выполнение на GitHub **не подтверждены**. Не считайте пример адреса развернутым сервером или прошедшие Python unit-тесты — успешной проверкой публичных VPN.

## Архитектура и ограничения

- Источники берутся **только** из белого списка `SOURCES` файла `checker.py` (стабильные ID совпадают с `ConfigSources.kt`). В первую очередь РФ: `avia`, `nikita`, `3inker`; добавлены источники резервного пула. Не принимать URL от пользователей, приватные подписки и загружаемый Xray JSON.
- На каждом запуске не более 80 конфигураций, 2 Xray-процесса одновременно, до 20 минут проверки и до 24 минут всего. Ротация по номеру Actions-run. Несуществующие или недоступные источники пропускаются. Максимум 2 URL на источник и 1 MiB на ответ.
- Xray берётся из **официального** `ghcr.io/xtls/xray-core` релиза `26.10.21` с закреплённым immutable **Linux amd64 SHA-256 OCI digest** `447ffc750a0b87d6e4f2c38425f68105bfc8c789e59c22d83b94eb7e1e648c50`. Это digest образа, НЕ SHA ZIP-архива; контейнер копирует `/usr/local/bin/xray` без исполнения установочных скриптов. В отсутствие Docker или доступа к образу workflow завершится ошибкой, фиктивные результаты не публикуются.
- Обязательны публичный IP узла, DNS-разрешение без private/link-local/loopback/CGNAT, закрепление адреса IP перед запуском Xray, SOCKS **только на 127.0.0.1**, HTTPS TLS+валидация сертификата `www.gstatic.com/generate_204`, затем независимо `www.youtube.com/` через тот же SOCKS. YouTube-проверка страницы **не гарантирует 720p**.
- Успешным считается только `https_ok: true`. Из feed никогда не публикуются исходные `vless://`, `vmess://`, `trojan://`, `ss://` URI, реальные пароли, IP или Xray outbound; только SHA-256 fingerprint, ID источника и признаки/время проверки.
- Источник `source_id` должен точно совпадать с `ConfigSource.id`. Fingerprint = SHA-256 от UTF-8 строки URI после trim и удаления всего начиная с первого `#`. Unicode в комментариях не влияет. Эквивалентные URIs с разной кодировкой параметров дают **разные** fingerprints. Тестовые URI `tests/fingerprints.json` — синтетические, не настоящие VPN-сервера.
- Повторно публикуются только ранее действительно проверенные HTTPS-success записи с исходным `checked_at`, если они моложе 8 часов. Новый неудачный пробный запуск удаляет проверенный узел из списка. При нуле новых успехов публикуется корректный JSON с пустым массивом либо с ещё актуальными старыми данными, не «фальшивые зелёные» узлы.

## Ручная публикация с телефона без платежей

1. Через GitHub web (в мобильном браузере при необходимости включите **«Версия для ПК»**) создайте **публичный** репозиторий, например `secureconnect-free-checker`. Если репозиторий уже есть, убедитесь, что он предназначен для этого проекта. Не загружайте в него личные VPN-подписки, ключи, `*.keystore` и секреты приложения.
2. Поместите **содержимое этой папки** в корень репозитория, а не сам ZIP. Не потеряйте путь `.github/workflows/verify-nodes.yml` (папка `.github` скрытая на некоторых файловых менеджерах). Удобнее загрузить через Git в Code on the go или любую бесплатную Git-программу на телефоне. Команды после `git init -b main`: `git add .`, `git commit -m 'Initial free checker'`, `git remote add origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПО.git`, `git push -u origin main`. GitHub потребует вход через credential manager или PAT с ограниченными правами; **не вставляйте PAT в исходники**.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**. Пока страница не включена, `deploy-pages` может не сработать.
4. Вкладка **Actions → Public VPN ranking (bounded Xray checks) → Run workflow → Run workflow**. После завершения откройте два job: `verify` и `deploy`; оба должны быть зелёными. Первый запуск может вернуть пустые `results`, если публичные источники/узлы недоступны из сети Github.
5. Проверяйте опубликованный файл по `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПО/feed.json`: HTTP 200, `"schema":1`, актуальные `generated_at`/`valid_until`, `"results":[...]`. **Это формула URL, а не проверенный действующий адрес!** Если Pages отдаёт 404, проверьте зелёный deploy и настройку Pages, не используйте URL в приложении как работающий.
6. Android: **Настройки → Бесплатный рейтинг GitHub Pages → HTTPS-адрес → Сохранить адрес рейтинга**. Перезапустите приложение или откройте его главный экран. Начальный запуск и восстановление VPN не зависят от загрузки JSON; в диагностике доступны причина fallback, время публикации и число сопоставленных узлов.

В `.github/workflows/verify-nodes.yml` есть `workflow_dispatch`, расписание в 01:23/07:23/13:23/19:23 UTC и запуск при изменении кода/тестов. Scheduled GitHub Actions может опоздать, быть пропущен или отключиться через 60 дней без активности публичного репозитория; тариф публичного standard runner сейчас бесплатен, но **не бессрочный SLA и не гарантия приемлемости конкретной нагрузки по GitHub ToS**. Если GitHub ограничивает проект, уменьшите лимит/частоту или отключите расписание, а не обходите защиту. GitHub запрещает использовать Actions как универсальную серверлесс-службу; загрузка маленького JSON как результата тестов проекта не гарантирует разрешение на регулярную внешнюю прокси-проверку — при сомнении обратитесь в GitHub Support.

Перепубликация сырой подписки **не производится**, но условия каждого внешнего источника могут изменяться: перед включением нового источника проверьте его лицензию и разрешённые методы запроса. Недоступные/отзывающие доступ источники следует исключать.

## Тесты

`python3 -m unittest discover -s tests -v` из корня checker. Должны пройти тесты fingerprint, UTF-8, source parsing, SSRF, DNS pin, дедупликации и TTL. Эти тесты **не требуют сети** и **не проверяют живые VPN**. Для реального теста workflow необходимы DNS/интернет, официальный Xray и публичные источники. Дополнительная ручная проверка должна исключать токены в логах и содержимом feed.

## Безопасность и конфиденциальность

Поскольку URI содержат публично опубликованные учётные параметры, они используются только в краткоживущих конфигурациях Linux runner c правами 0600, удаляются после пробы, stdout/stderr Xray отключены. Это не является гарантированной изоляцией недоверенного кода уровня VM для Xray; если появятся уязвимости в Xray, остановите проверки и обновите закреплённый образ после проверки digest. Запросы только по фиксированным HTTPS URL от GitHub; редиректы заблокированы. Feed клиента Android не может добавлять конфигурации, менять routing, подключать VPN или подтверждать 720p.

## Почасовая проверка (26.10.2026)

- GitHub Actions запускает ограниченный тест в 23-ю минуту каждого часа UTC (`23 * * * *`). GitHub может задержать запуск.
- За один запуск проверяется не более 24 кандидатов в двух потоках; старые подтверждения хранятся только до истечения `checked_at`.
- Для резервного ручного запуска обновите `ops/hourly-trigger.txt`: это вызывает push workflow. Делайте это лишь когда расписание пропущено и другой запуск уже не работает.
- Дополнительная почасовая задача ChatGPT проверяет актуальность `feed.json` и при пропущенном обновлении может отправить резервный триггер через подключённый GitHub. Выполнение зависит от доступности GitHub и инструмента.
- Только публичный репозиторий и стандартные бесплатные runners, без VPS, API и подписок. Соблюдайте [ограничения GitHub Actions](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features).

## Проверка восстановления Xray / GitHub Actions (27.10.2026)

После первичного HTTPS-теста до **трёх успешных публичных маршрутов из разных источников** повторно проверяются запуском нового процесса Xray и нового SOCKS/TLS-запроса. Результат `restarts.json` показывает `restart_ok` и задержку повторной проверки. Ни VPN URI, ни пароли в этот диагностический JSON не включаются. Результат подтверждает **только повторную работоспособность через GitHub runner** — это не тест Android VpnService, TUN, смены сети или работоспособности в мобильной сети пользователя. Лимиты: максимум 24 первоначальные проверки и до 3 повторных, 2 потока.


## CI: инъекция отказов Android (28.10.2026)
В `android/ci-tests/CiFailureRecoveryMatrixTest.kt` находятся тесты существующих решений Guardian/QuickConnect/FastFailover на холодный TLS, повторные ошибки, пропадание физической сети, порядок проверенных/облачных маршрутов и изоляцию ручного выбора. Workflow `android-build.yml` переносит их в тестовый исходный проект и исполняет `:app:testDebugUnitTest`; JUnit XML публикуется отдельным артефактом. Это **симуляция событий и проверка Android Kotlin-политик**, не тест фактического Android VpnService/TUN и не сертификация безопасности APK. Живые подключения Xray на GitHub проверяются отдельным `verify-nodes.yml` вместе с перезапуском реального процесса Xray (до 3 серверов). Play Protect-замечание для debug APK остаётся открытым, новую установку не предлагаем.
