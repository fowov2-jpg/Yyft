# VipineshkaVPN — рабочая ветка переделки для России

Дата: 2026-10-30. Ветка: `feature/vipineshka-russia-one-tap-20261030`.

## Найденная рабочая база
- `android/source.zip` существует в репозитории (381211 байт). Использовать **эти исходники SecureConnect**, а не заменять их отдельным демонстрационным приложением.
- `.github/workflows/android-build.yml` извлекает `SecureConnect-2.4.7/`, накладывает патчи `android/patches/apply_one_tap.py` и `apply_session_timer.py`, собирает, тестирует, запускает lint и проверяет APK. Итоговый debug artifact помечен 2.4.8.
- `checker.py` и `feed.json` остаются общими с production. Работающая публикация рейтинга в `main` НЕ должна ломаться.

## Границы текущего этапа
Создание этой ветки и воспроизводимой CI-сборки исходного VPN **не означает**, что новый UI или транспорт для ограниченных российских сетей уже внедрён. Отдельные preview-файлы из предыдущих ZIP не заменяют текущий Xray/TUN движок. Нельзя публиковать preview APK как работающий VPN.

## Спринт 1 — надёжная однокнопочная логика
1. Изучить фактические `VpnService`, ViewModel, Xray bridge, диагностику и существующий stop/recovery flow в `android/source.zip`.
2. Исправить `Verified pool ready: 0/21`: различать cloud-confirmed и locally-qualified, анализировать сопоставление fingerprint и source_id, обрабатывать устаревший feed и сетевые ошибки.
3. После нажатия «Подключиться» выбирать реальные локально доступные маршруты; учитывать ошибки TLS, DNS, IPv6 и измеренное время отклика.
4. Статус «Защищено» показывать только после действующего туннеля и успешной проверки полезного трафика через него. Нельзя имитировать 2–3× ускорение.
5. STOP — единая идемпотентная операция: отмена повторных попыток, закрытие TUN/Xray, закрытие собственного foreground-уведомления, сброс UI. Отдельно проверить удаление из недавних на Xiaomi и взаимодействие с Always-on.
6. Встроить новую визуальную систему (корона, фиолетовый/бирюзовый, экраны подключения/серверов/настроек), не подменяя engine демонстрационным классом.

## Россия и белые списки операторов
- Проверять реальную достижимость **разрешённого пользователем** VPN-шлюза из мобильной сети устройства, а не только GitHub runner.
- `Host`, `Forward Host`, `User-Agent` и HTTP-BUG из TLS Tunnel — не универсальная техника ускорения и не доказательство доступа через whitelist. Не имитировать трафик vk.com, не подменять чужие домены и TLS-сертификаты.
- Если доступ к VPN-шлюзу заблокирован оператором, приложение должно честно сообщить о недоступности, а не изображать «ВК-трафик». Для реального подключения необходим достижимый доверенный шлюз и работоспособный туннель.
- Замеры скорости: одинаковые условия и нагрузка до/после, ограниченный бюджет трафика, без обещаний конкретного множителя.

## Релизные проверки
- Обязательны Android `assembleDebug`, unit tests, lint, security audit и проверка подписанного APK.
- Испытания на реальном устройстве в России: Wi-Fi, МТС/МегаФон/билайн/t2 по доступности; DNS, IPv6, kill switch, реальная передача трафика и аварийный STOP.
- Debug APK из CI может быть несовместим по подписи с установленной версией; не удалять рабочий VPN без резервной копии.
- Изменения внедрять только в этой ветке; `main` не трогать до прохождения проверок.

## Сборка
Ветка содержит экспериментальный workflow `.github/workflows/build-vipineshka-branch.yml`, который повторяет существующие проверки исходного SecureConnect и сохраняет отдельный debug-артефакт. Это APK исходного движка с уже существующими патчами, **не завершённый редизайн**.
